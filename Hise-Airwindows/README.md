# Hise Airwindows

A HISE / scriptnode port of the [Airwindows](https://github.com/airwindows/airwindows)
effects by Chris Johnson — 360+ effects wrapped as native scriptnode nodes. The
original DSP is compiled unmodified; a thin wrapper exposes each effect to HISE.

## The files that matter

| File | Why it matters |
|------|----------------|
| [`src/airwindows/AirWindows.h`](DspNetworks/ThirdParty/src/airwindows/AirWindows.h) | Shared wrapper. Lets the unmodified Airwindows source build as a scriptnode node and surfaces each effect's parameters with their real names (e.g. *Limit*, *Dry/Wet*). Required by every effect. |
| `DspNetworks/ThirdParty/<Effect>.h` | Per-effect wrapper (autogenerated). Includes the shared wrapper + the raw DSP, then declares the node. See [`Acceleration.h`](DspNetworks/ThirdParty/Acceleration.h). |
| `DspNetworks/ThirdParty/src/airwindows/<Effect>/` | The raw DSP, copied verbatim from Airwindows. Three files: `<Effect>.h` (declaration), `<Effect>.cpp` (parameters/names), `<Effect>Proc.cpp` (processing). |
| [`src/airwindows/1-what.txt`](DspNetworks/ThirdParty/src/airwindows/1-what.txt) | One-line description of every effect — the reference for what each does. |

The main wrapper entry point is:

- [Airwindows.h](https://github.com/mzajner/Hise-FxLibraries/blob/main/Hise-Airwindows/DspNetworks/ThirdParty/src/airwindows/AirWindows.h)

From inside HISE: top toolbar → `Export` → `Compile DSP networks as dll`.

### Troubleshooting: HISE reports `BUILD FAILED` (or crashes) on compile

HISE doesn't compile this itself — it re-saves the project and runs the same
`xcodebuild`/clang as everything else, so this is not a compiler or node-count
limit (the full library builds clean). An *instant* failure almost always means
the build never started, usually a locked build database: JUCE builds into the
project-local `DspNetworks/Binaries/Builds/MacOSX/build/`, so if that Xcode
project is open or building at the same time, HISE's `xcodebuild` can't attach
(`error: database is locked … two concurrent builds`).

- **Close the autogenerated Xcode project (and any running build) before
  compiling from HISE.**
- Or build it directly: open
  `DspNetworks/Binaries/Builds/MacOSX/Hise-Airwindows.xcodeproj` in Xcode, or run
  `DspNetworks/Binaries/batchCompileOSX.sh` with Xcode closed.

The build's HISE/JUCE paths come from HISE's settings; if a build fails with
`'juce_core/juce_core.mm' file not found`, point HISE at the correct HISE source
folder and re-export.

## Use one effect in another project

Copy these, keeping the layout:

```
DspNetworks/ThirdParty/
├── Acceleration.h                 # per-effect wrapper
└── src/airwindows/
    ├── AirWindows.h               # shared wrapper (required by all)
    └── Acceleration/              # raw DSP folder
        ├── Acceleration.h
        ├── Acceleration.cpp
        └── AccelerationProc.cpp
```

HISE registers the node automatically when you compile the DSP networks.
